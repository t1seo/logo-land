# 대화형 로고 생성 플러그인 실행 계획

## 목표

다섯 로고 제작 서비스의 공개 제작 흐름을 실제 화면과 공식 문서로 조사하고, 그 결과를 Codex에서 브랜드 상담 → 로고 시안 생성 → 선택 → 수정 → 파일 전달로 이어지는 플러그인으로 구현합니다. 사용자가 Codex 직접 생성 방식을 명시적으로 확정했습니다. 별도 웹 앱이나 유료 SaaS 자동 결제 기능은 포함하지 않습니다. 실행·검토는 Orca Run `run_fdd802989645`로 추적합니다.

## 요구사항과 결정

- 조사 대상: Looka, Brandmark, Tailor Brands, Fiverr Logo Maker, Design.com.
- 조사 자료: `docs/research/`의 한국어 보고서, 출처 목록, 실제 PNG/JPEG 화면, 단계별 스냅샷, 비교표와 탐색 색인.
- “모든 방법”의 범위: 공개적으로 발견되는 신규 생성 경로, 로고 유형, 입력값, 추천·검색·생성, 편집, 저장·내보내기, 관련 브랜드 자산. 계정·결제·사람 확인 뒤 기능은 직접 확인 여부를 표시합니다.
- 실제 생성은 현재 호스트의 내장 이미지 도구가 담당합니다. Python 도구는 입력 파싱·파일 보존·검증·출력 포장만 담당합니다. API 키를 요구하거나 숨은 API로 전환하지 않습니다.
- 조사 중 사이트가 계정을 요구하면 개인 Google 계정으로 회원가입·로그인하도록 사용자가 허용했습니다. 브라우저에서 가능한 계정 흐름을 사용하며, 비밀번호·MFA 입력이 필요한 경우에는 이를 제한으로 기록합니다. 계정 선택 화면은 자료에 저장하지 않습니다.
- 사용자와의 대화가 UI입니다. 이미 받은 브리프는 다시 묻지 않으며, 중요한 누락 정보만 1–3개의 짧은 질문으로 받습니다. 충분한 정보와 생성 요청이 있으면 바로 실행합니다.
- 주요 로고 유형: 워드마크, 레터마크, 모노그램, 심볼, 추상, 조합형, 엠블럼, 마스코트. 유형과 미니멀·빈티지 등 스타일을 별도 차원으로 취급합니다.
- 새 이미지, 스타일 참고 이미지가 있는 새 생성, 기존 이미지 수정, 선택안 변형, 재개를 지원합니다. 미리 정해진 개수는 강제하지 않으며 기본 시안은 3개입니다.
- 내장 도구 산출물은 래스터입니다. 실제 PNG를 검사하여 전달하며, 투명 배경은 알파와 화면 검사 후 표시합니다. SVG/EPS/AI는 별도 벡터 제작과 검증 없이는 제공했다고 말하지 않습니다.
- 사용자 데이터는 실행 workspace에 저장합니다. 플러그인 설치 캐시에 세션을 저장하지 않습니다.

## 실행 순서와 의존성

1번은 병렬 조사, 2번은 설계입니다. 3번과 4번은 계획에 따라 독립적인 책임으로 구현합니다. 5번은 구현 통합 후 실제 사용, 6번은 독립 검토, 7번은 전달입니다. 새 worktree 없이 같은 저장소에서 파일 소유권을 분리합니다.

| 작업 | 선행 | 담당 |
|---|---|---|
| 1. 조사와 증거 | 없음 | 코디네이터 + 공식 문서·브라우저 조사 작업자 |
| 2. 계획과 계약 | 초기 조사·Metis | 코디네이터 |
| 3. helper와 테스트 | 2 | 구현 작업자 |
| 4. 대화 스킬과 manifest | 2 | 코디네이터 |
| 5. 실제 생성·편집·재개 QA | 3, 4 | 코디네이터 + 독립 QA |
| 6. 다섯 관점 검토 | 1, 3, 4, 5 | Orca 검토 작업자 |
| 7. 패키지·최종 안내 | 6 | 코디네이터 |

## 작업별 수용 기준

- [x] 1. 다섯 사이트의 제작 흐름과 주요 분기 조사.
  - 각 서비스에 진입 화면, 관찰한 입력·생성·편집 단계 PNG/JPEG와 실제 URL을 연결합니다.
  - 기본 브리프는 가상 브랜드 `Morrow Studio`, 디자인 스튜디오, 녹색·미니멀로 통일합니다.
  - 공개 공식 문서로 유형·편집·형식·가격/제약을 보완하고 출처를 붙입니다.
  - QA 정상: 스크린샷 파일이 열리고 보고서 링크가 실제 파일을 가리킵니다.
  - QA 제한: Fiverr 사람 확인, 로그인 또는 결제 화면은 제한으로 기록하고 성공한 생성처럼 서술하지 않습니다.
  - 증거: `docs/research/`.

- [x] 2. Metis 검토를 반영하여 이 계획과 책임 경계를 확정합니다.
  - 구현 인터페이스는 CLI JSON 입력/출력. create, show/list, prompt, import, select, review, export에 해당하는 명령을 제공합니다.
  - 생성과 수정 작업은 실제 tool 호출을 스킬에서 수행하고 최종 prompt와 부모 시안 관계를 기록합니다.
  - 모든 작업은 요청된 로컬 변경만 포함하며 커밋·게시·결제는 하지 않습니다.
  - 증거: 이 문서와 `docs/planning/gap-analysis.md`.

- [x] 3. 타입이 있는 세션·이미지 보존 helper를 구현하고 테스트합니다.
  - Python 3.12 이상, uv, Pydantic v2, Pillow, pytest, Ruff, basedpyright를 사용합니다. 단일 모듈은 250 코드행 이하입니다.
  - 브리프: 브랜드명, 정확한 문구/슬로건, 업종·대상·스타일·유형·팔레트·금지사항·활용처.
  - 상태: schema_version, id, revision, timestamps, brief, artifacts, selected_id, 생성/수정 prompt, parent_id, hash, 크기/형식/알파, 시각 검토 결과.
  - 형식 검사·전체 투명 파일 거부·원본 보존·경로 탈출 방지·충돌 거부·손상 상태 오류를 구현합니다. 파일 검증 전 성공 상태를 쓰지 않습니다.
  - PNG 파일을 실제 형식으로 검사하며 내용 변환은 수행하지 않습니다. ZIP에는 선택 파일과 정직한 metadata/brand-guide를 넣습니다.
  - QA 정상: 임시 폴더에서 브리프 생성 → 시안 import → 선택 → 검토 → export → 새 프로세스 show → ZIP hash 일치.
  - QA 오류: 손상/위장 PNG, opaque RGBA의 투명도 오표기, 전부 투명, 중복 ID, 존재하지 않는 부모, 경로 탈출, stale revision, 미지원 상태 버전.
  - 증거: `docs/qa/helper-tests.md`, 자동 테스트 실행 결과.

- [x] 4. 대화형 스킬·유형별 프롬프트·manifest·사용법을 작성합니다.
  - 생성 요청 시 실제 내장 도구를 호출하고 각 시안에 안정적인 ID를 붙입니다. 결과를 보지 않고 품질 통과를 기록하지 않습니다.
  - 로컬 수정 대상은 먼저 이미지로 열고 정확한 파일을 참조합니다. 원본은 보존하며 v2/v3를 만듭니다.
  - 도구 미노출은 설명 가능한 미완료 상태입니다. 무단 API fallback 또는 가짜 PNG/SVG 대체는 금지합니다.
  - README에 설치·사용 예제·실행 요건·검증 범위를 명시합니다.
  - QA 정상: 공식 plugin validator와 skill validator 통과, 다른 경로에 복사해 helper 실행.
  - QA 오류: 이미지 도구 없는 환경을 위한 동작 시나리오를 독립 스킬 실행으로 확인합니다.

- [x] 5. 실제 생성과 수정, 전달을 실행합니다.
  - 가상 브랜드로 최소 2개의 독립 시안을 내장 도구로 생성합니다.
  - 한 시안을 실제 참조하여 색상 또는 구성 수정 1회. 입력과 결과, prompt, 부모 관계를 저장합니다.
  - 완성 이미지를 직접 보고 문구·잘림·실루엣·배경·작은 크기 식별성을 검사합니다.
  - 통과한 시안을 선택·검토·내보내고 ZIP 내부와 해시를 확인합니다. 시각 결과가 나쁘면 수정합니다.
  - QA 오류: 실패한 생성은 생성된 것으로 등록하지 않으며 마지막 정상 원본을 보존합니다.
  - 증거: `docs/qa/`와 `output/logo-generator/`.

- [x] 6. 구현 후 독립 검토를 실시하고 발견된 결함을 수정합니다.
  - 계획 준수, 코드 품질, 보안/데이터 보존, 실제 사용, git/요구사항 문맥 다섯 관점으로 Orca 작업을 분리합니다.
  - 리뷰어는 읽기 전용이며 QA만 임시 폴더에 출력합니다. 별도 API 호출과 계정 변경은 하지 않습니다.
  - QA: 실패 증거가 있으면 수정 후 관련 검증을 다시 수행합니다. 근거 없는 “통과”는 인정하지 않습니다.

- [x] 7. 자료 색인과 설치 가능한 플러그인 패키지를 전달합니다.
  - 연구와 실제 예제는 플러그인 런타임에 불필요하게 포함하지 않습니다.
  - 사용법, 생성 예제, 테스트 결과, 관찰 불가능한 범위를 함께 안내합니다.
  - 설치/새 대화 등록까지 확인하지 않았다면 설치 완료라고 하지 않습니다.

## 완료 기준

조사 문서와 캡처가 다섯 사이트를 모두 다루고, 대화 스킬이 실제 로고 생성·수정·전달에 사용되며, 코드 검사와 데이터 보존 테스트가 통과하고, 남은 관찰 제한이 명시되어야 합니다. 연구에서 확인한 유료 서비스의 모든 기능을 그대로 복제하는 것이 아니라, 사용자가 요청한 Codex 대화형 로고 제작 과정을 끝까지 제공하는 것이 제품 범위입니다.
