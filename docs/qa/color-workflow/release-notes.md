# Logo Land 0.4.0 — development preview

This is an **unpublished release draft**. The source and personal development installation use 0.4.0; the latest published release remains 0.3.1.

Logo Land now accepts automatic color selection, a fixed anchor, a restricted palette, reference-image colors, and combinations of these choices. Each image retains its palette version. Reference extraction and color analysis run locally, while the Codex native image tool creates and edits the actual logo.

Horizontal and stacked symbol-plus-text layouts record symbol position, alignment, exact lettering and typography appearance. New research covers Google Fonts, Adobe Fonts, community skills/MCPs and Korean/Latin font references. A requested font name remains visual intent; no font files are installed or bundled.

Session schema 2 reads schema 1 without rewriting it. The first successful mutation saves an exact v1 backup. Old releases cannot read v2 sessions. Export manifest schema 2 separates intended colors from sampled raster evidence and recomputes strict checks from the selected original. PNG bytes and the three ZIP payload files are preserved.

English and Korean READMEs include real samples. The new gallery shows eight native requests, all 16 generated originals and an additional copied parent, per-image color reports, full repair histories and light/dark/small previews. NORTHLINE, GROVE and TIDE were reviewed and exported successfully.

The final source suite recorded 315 passing tests, clean lint/types/format checks and locked dependencies. This includes a correction preserving accepted legacy/advisory PNG exports when optional EXIF color analysis is unavailable, with strict refusal and original-byte integrity retained. Unsupported ICC reasons are preserved. Installed-cache checks and independent reviews are recorded in the [validation record](https://github.com/t1seo/logo-land/blob/main/docs/qa/color-workflow/README.md).

## Why publication is withheld

The plan requires successful restricted-color and white-transparent native samples. These remain unresolved after two additional edits per affected request. Some edits painted an opaque checkerboard; other candidates retain excessive partial alpha under the declared sampling policy. The white variant looks clean in the Chrome gallery, which is separate from its indeterminate alpha evidence. These results are preserved as failures or indeterminate evidence, and are not delivered as approved logos. The SUNROOM subtitle is also too small at 128px.

Sampling does not guarantee exact pixel colors, print/Pantone matching, exact font outlines, editable vectors or accessibility. No thresholds were weakened, no original pixels were altered programmatically, and no synthetic fixture is presented as native-generation success.

Publish only after the remaining native sample requirements and all final review requirements are satisfied. No public v0.4.0 tag is created by preparing this draft.
