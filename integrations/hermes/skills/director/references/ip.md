# IP character recipe

Adapted from [s1dashu/ip-as-logo-skill](https://github.com/s1dashu/ip-as-logo-skill/blob/acb834c717bcd0a487c49732d08397ba280d690b/SKILL.md),

By default propose three product-relevant character subjects or, when a subject is
specified, three treatments of that subject. The default six candidates contain two
distinct takes per direction, one lower-left and one lower-right. Honor an explicit
supported count; every candidate is its own original image, never a grid.

Use one upright, personified subject with extremely simple, heavy rounded forms,
roughly four to seven basic shapes. Fill most of the square from a dominant lower
corner, keeping recognizable facial features visible. Do not add a centered safe
margin instruction that undoes the corner composition. Keep decoration sparse.

Use two purposeful subject color families and one solid background color. Reuse the
subject colors for the face. In the absence of supplied colors, warm yellow and deep
navy on muted sage are a starting proposal. These are visual roles, not a pixel-color
limit; preserve incidental tonal variation. User-supplied colors take precedence.

The final image prompt describes only the character, shape, pose, corner placement,
colors, face and a background filling the whole square. Avoid logo/app-icon/use-case
framing and alpha/opaque/transparency vocabulary in that prompt. Say, for example,
“solid muted sage filling the entire square.” For white, say “solid white #FFFFFF
filling the entire square.” Request approximately 1536 by 1536 in prompt text, and
record actual returned dimensions rather than treating the request as evidence.

This adaptation preserves the upstream character geometry, semantic color roles,
corner composition and independent-draw process. Logopia adds saved provenance,
target-size pixel reviews and exact-parent revisions. No upstream executable code
or showcase image is bundled.
